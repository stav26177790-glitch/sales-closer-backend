### 0.3. Продукт: что делает Клоузер (решения владельца)

- **Главная задача: помочь менеджеру закрыть сделку в размещённый заказ.**
- Работает с **«зависшими» сделками — как правило, после КП** (воронка 1, этапы 07–08).
- **Менеджер не оценивает качество** (у него нет базы знаний — за этим он и идёт к Клоузеру) и **не
  составляет касания**. Его роль: дать переписку, ответить на вопросы о фактах, отправить касания,
  вернуть ответ клиента. Владелец — эксперт, иногда смотрит сессии. Claude — превращает замечания в правила.
- **Путь без остановок** (`engine/autoFlow.js`): менеджер присылает переписку → один ход:
  оценка → стратегия → проверенные касания; части появляются в чате по мере готовности
  (фронт подгружает по `job.parts`). «ок» не нужен. Остановки — только за фактами: нет сроков
  (один вопрос до старта, «без срока» — дальше), уточнения planner'а, расхождение с самооценкой
  менеджера, шаг не удался.
- **После касаний** менеджер вставляет ответ клиента / пишет, что нового → **путь перестраивается целиком**
  (`composing.js` isNewFacts → rebuildPath). Явная правка текста («касание 2 короче») — только тексты;
  вопрос («что ответить на дорого?») — advisor; «ок» — итог сессии (memory).
- Менеджеру — «✅ Касания готовы» + «Клиент ответил или что-то изменилось — вставьте ответ…». Отладка
  (ход проверки, замечания, «приняла не всё») — только в выгрузке (`last_composer_output._check`:
  trace, approved, needs_review).
- **Формула 100% закрытия**: ФВ (финансовая возможность), ОП (осознанная потребность), ЛПР (определён),
  Д (доверие), ЗС (здесь и сейчас = клиент готов запускать в работу; срочность — часть ЗС).
  Статусы Подтверждено / Вероятно / Неизвестно / Риск. Во фронте лампочки ФВ/ОП/ЛПР/Д/ЗС.
- **СОПРАНО** (С-ситуация, О-опыт, П-проблемы, Р-решение, А-аналоги, Н-нюансы, О-ограничения/бюджет)
  — вопросы менеджера (за сбором следит робот Битрикс24). Клоузер только отмечает, что собрано, и даёт
  **≤3 рекомендации**; на статусы и касания напрямую не влияет; путь не останавливает. При возражении по
  цене — рекомендация выяснить бюджет (код `ensureBudgetRecommendation`).
- Шесть триггеров клиента (`knowledge/24_client_triggers.md`): Прибыль, Удобство, Надёжность, Тщеславие,
  Новизна, Симпатия — только по цитате и только того, с кем общались.

### 0.4. Бизнес-правила владельца (все в коде/промптах; полный список — `RULES.md`, 44 правила)

- Цена в КП **фиксированная** («по цене из КП, без доплат по ходу»). Скидку не предлагать; на «дорого» —
  сначала выяснить, что стоит за этим (бюджет, сравнение, ценность). Альтернатива (размер/материалы) —
  одной фразой, без новых цифр, только по поводу клиента.
- Монтаж всегда **2–3 рабочих дня** (и у баннера). Временная вывеска (баннер): 3–4 раб. дн. + монтаж 2–3,
  только если постоянную не успеваем/впритык; цену баннера не называть («сориентирую»).
- Сроки считает **код** (`engine/timeline.js`): рабочие дни, праздники РФ, в выходной — старт с ближайшего
  рабочего дня; `ready_if_start_on` — даты для касаний, уходящих позже; агенты даты не считают.
- Касания после КП: **≥2 отработанных возражения**, **чередование экспертное/эмпатичное**, эмпатичное =
  **кружки** (речь в камеру 20–40 с, без «[фото]»), совместное событие с ЛПР ≥2, ДЧЕТ
  («Давайте / Чтобы / Если / То»), down/up-sell, сроки и слоты (цену держим).
- Выход на ЛПР — **только с согласия контактного лица** (никаких «не через Марину», «в обход»).
- Обещанное клиентом (логотип и т.п.) — просить по **шаблону владельца**: «Помните, мы проговаривали,
  что пришлёте логотип? Скинете сейчас — это позволит нам держаться в графике, я сразу отдам дизайнеру и
  вы получите готовую визуализацию» (формула «давайте… если… то» с выгодой клиента, без упрёка).
  Если позже в переписке уже прислано — не просить.
- **«Кстати, можно один вопрос?»** — классическая подводка, разрешена.
- Если менеджер раньше называл условие («успеваем, если согласуем до 10 ноября») — честно сослаться.
- **Спящий режим**: только после **7 касаний** без ответа, на **30–40 рабочих дней**, затем одно касание
  «как дела, какие результаты». Не «после 5 — потерянная».
- Запрещено (код `phraseCheck.js`): «сроки зависят только от нас», «гарантированно/точно успеем»,
  упрёк «вы обещали», «нужно решение сегодня» / «решение до конца сегодня» / «без вывески совсем»,
  угроза «слот уйдёт», выдуманные кейсы («пока ждал — смонтировали…»), выдуманные цифры/рейтинги/отзывы.
- Реальные факты компании — `knowledge/industry/signage.md` по сайтам msk-viveska.ru и metallbukva.ru
  (14.11): два бренда, гарантии по бренду, кейсы. Рейтингов нет — доверие через кейсы.
- Материал для пересылки ЛПР («одна страница») — можно длиннее (лимит письма), начинается с выгоды ЛПР.

### 0.5. Архитектура (коротко)

- `engine/advance.js` — один ход машины состояний (`opts.path` — режим пути); `engine/autoFlow.js` —
  путь без остановок; `engine/steps/*` — этапы (intake, diagnosing, strategySelection, composing,
  conflict, escalation/reviewing — legacy, newSession, finalize).
- Касания: стратегия даёт `touchpoint_sequence` → **код** строит план `touch_plan`
  (`engine/touchPlan.js`: даты, канал, тип, чередование, вставка кружка, условия, факты на день отправки)
  → `writer` пишет тексты по плану → **код** приколачивает канал/дату/тип (`pinToPlan`) →
  `composeUntilReady` (`engine/autoCompose.js`): проверки кода (длина, чередование если нет плана,
  кружок, пропущенные касания) → `editor` (точечно) → `reviewer` (≤2 раза; второй — только правленые
  касания, `review_only`; ответ компактный) → финальный `editor`. Reviewer не спорит с кодом
  (`applyCodeOwnership`), «совет» не блокирует (`applySeverity`).
- «Обязательно в касаниях» (`engine/mustInclude.js`): сроки из расчёта, обещания менеджера и клиента из
  переписки (без повторов, уже выполненные — не добавляются).
- Код-чистки: `diagnosticCleanup.js` (обход контактного лица, «ЗС», бюджет в СОПРАНО),
  `strategyCleanup.js` (спящий режим), `phraseCheck.js`, `scheduleCheck.js`, `jsonRepair.js`
  (прямые кавычки внутри JSON-ответа модели).
- Фоновые ходы: `POST /api/deals/:id/continue {async:true}` → 202; `GET /api/deals/:id/job`
  (stage, parts, elapsed); `GET /api/deals/:id/agent-calls` (выгрузка). Мягкое завершение при деплое (SIGTERM).
- Агенты (`llm/registry.js`): planner, diagnostic, strategy (8000 токенов), composer (legacy),
  writer, editor, reviewer (Sonnet); memory, advisor, intent_classifier (Haiku).
- Тесты: `npm test` = static-checks, снимки (`tests/scenarios.js`, `KLOUZER_TODAY=2026-11-13`, в т.ч. `path_*`),
  модульные (timeline, touchPlan, autoCompose, mustInclude, phraseCheck, scheduleCheck, diagnosticCleanup,
  strategyCleanup, jsonRepair, progress, errors, runner), виртуальный прогон `tests/virtual/run.js`
  (10 сделок пошагово + 9 в режиме пути).

## 10. Как добавить менеджера

Регистрация в Клоузере закрыта: менеджера добавляет владелец в Supabase.
Вход у менеджера — по ссылке на почту, пароля нет.

### Один раз: настроить свой SMTP

Без этого письма доходят только участникам команды Supabase и не больше 2 в час.

1. Нужен почтовый ящик, от имени которого пойдут письма. Проще всего — Яндекс:
   Яндекс ID → Безопасность → **Пароли приложений** → создать пароль для «Почты».
2. Supabase → **Authentication → Emails → SMTP Settings** (вкладка SMTP) → **Enable Custom SMTP**:
   - Sender email: адрес этого ящика; Sender name: `Клоузер`
   - Host: `smtp.yandex.ru`, Port: `465`
   - Username: полный адрес ящика; Password: пароль приложения из п.1
   - **Save**.
3. Supabase → **Authentication → Rate Limits**: при необходимости поднять лимит писем в час (например, 30).
4. Проверка: выйти из Клоузера и войти снова — письмо должно прийти от нового отправителя.

Для рассылок с корпоративного домена вместо Яндекса подойдёт любой SMTP-сервис
(Unisender Go, Brevo, Resend и т.п.) — поля те же.

### Пригласить менеджера

1. Supabase → **Authentication → Users** → **Add user** → **Send invitation**.
2. Ввести рабочую почту менеджера → **Send invitation**.
3. Менеджер получает письмо-приглашение, нажимает ссылку — открывается Клоузер, он уже вошёл.
   Профиль менеджера (`managers`) создаётся автоматически при первом входе.
4. Дальше менеджер входит сам: адрес Клоузера → почта → «Получить ссылку для входа».

Вариант без письма-приглашения: **Add user → Create new user**, почта, галочка
**Auto Confirm User**, пароль любой (не используется) — менеджер сразу входит по ссылке
со страницы Клоузера.

Каждый менеджер видит только свои сделки.

### Отключить менеджера

Внимание: удаление пользователя **удаляет все его сделки** (каскадом).
Чтобы сохранить сделки, сначала передайте их другому менеджеру в SQL Editor:

```sql
update deals
set manager_id = 'ID_КОМУ_ПЕРЕДАТЬ'
where manager_id = 'ID_УХОДЯЩЕГО';
```

ID — колонка UID на странице Authentication → Users. После этого: Users → строка
менеджера → меню «…» → **Delete user**.
